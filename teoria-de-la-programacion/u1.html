01Repaso

Lenguaje de programación

Conjunto de caracteres, reglas para combinarlos y reglas que especifican sus efectos al ejecutarse. No exige conocer código máquina, es independiente de la máquina, se traduce a lenguaje máquina y usa una notación más cercana al problema que al código máquina (Gallardo et al., 2025, §2.1).

Tiene sintaxis (reglas que definen qué textos son correctos) y semántica (reglas que definen el resultado de ejecutar el programa) (Gallardo et al., 2025, §2.5). Debe poder traducirse sin ambigüedad, pero lo leen, comentan y prueban personas (Gallardo et al., 2025, §2.6).

Abstracción

Dar un nombre a una entidad del lenguaje (una variable, una función, una clase) es construir una abstracción (Gallardo et al., 2025, §3). La informática tiene abstracciones de datos propias, como listas, árboles, grafos y tablas hash (Gallardo et al., 2025, §3.2).

Abelson y Sussman, citados en Gallardo et al. (Gallardo et al., 2025, §2.4), señalan tres mecanismos presentes en todo lenguaje: expresiones primitivas, mecanismos de combinación y mecanismos de abstracción, que permiten nombrar elementos compuestos y manipularlos como unidades.

Paradigma

Un paradigma es un enfoque de programación basado en una teoría matemática (Van Roy, 2009, §1). También se lo describe como un conjunto de características, patrones y estilos basados en una idea fundamental, que puede usarse en distintos lenguajes (Gallardo et al., 2025, §4.1).

  • Imperativo: un estado implícito se modifica mediante instrucciones, en una secuencia de pasos (Gallardo et al., 2025, §4.4).
  • Funcional: la computación se realiza evaluando expresiones; las funciones son datos y no hay efectos laterales (Gallardo et al., 2025, §4.2).
  • Lógico: definición de reglas y unificación; es declarativo (Gallardo et al., 2025, §4.3).
  • Orientado a objetos: clases, herencia, objetos como abstracción de datos y procedimientos, y polimorfismo (Gallardo et al., 2025, §4.5).

La programación declarativa le dice a la computadora qué se necesita en lugar de cómo calcularlo (Van Roy, 2009, §1).

Multiparadigma

Son lenguajes creados con la intención explícita de fusionar más de un paradigma; Scala, por ejemplo, combina orientación a objetos y programación funcional (Gallardo et al., 2025, §4.1). La documentación de Python indica que soporta varios paradigmas además del orientado a objetos, como la programación procedural y la funcional (Python Software Foundation, s.f.-b).

Traducción
  • Compilar es traducir el código fuente a otra forma, normalmente de más bajo nivel, como bytecode o código máquina. Un compilador traduce pero no ejecuta; un intérprete ejecuta el programa directamente desde el código fuente (Nystrom, 2021).
  • Un programa C compilado para un procesador produce código máquina que solo corre en ese tipo de procesador (Gallardo et al., 2025, §5.1).
  • Enfoque mixto: javac traduce Java a un código intermedio llamado bytecode, que luego interpreta la máquina virtual (Gallardo et al., 2025, §5.3).
  • CPython compila el código fuente Python a bytecode, que se ejecuta en una máquina virtual (Python Software Foundation, s.f.-c). Por eso CPython es un intérprete que además tiene un compilador (Nystrom, 2021).
Diseño

Los lenguajes deben ser precisos para la máquina y, a la vez, adecuados para las personas que los usan (Gallardo et al., 2025, §2.6). Los criterios de diseño se estudian en la Unidad 2.

Futuro

Cada vez es más fácil crear lenguajes nuevos: ya no surgen solo en grandes departamentos de investigación, sino también en comunidades de código abierto (Gallardo et al., 2025, §1.6.1). Van Roy sostiene que los lenguajes deberían soportar muchos paradigmas (Van Roy, 2009, §1).

No confundas

«Interpretado» no significa «sin compilación». CPython compila el código fuente a bytecode antes de ejecutarlo (Python Software Foundation, s.f.-c; Nystrom, 2021). Los errores de sintaxis se detectan al interpretar el código; las excepciones aparecen durante la ejecución (Python Software Foundation, s.f.-a, §8.1–8.2). La actividad 3 te permite comprobar la diferencia.

02Código comparado

La misma suma en tres paradigmas

Las tres versiones calculan la suma de los dobles de una lista. Observa quién controla el proceso y dónde está el estado.

numeros = [3, 4, 5]
total = 0                      # estado que va cambiando
for n in numeros:
    total = total + n * 2
print(total)

Salida al ejecutarlo: 24

numeros = [3, 4, 5]
total = sum(n * 2 for n in numeros)   # se declara el resultado
print(total)

Salida al ejecutarlo: 24

class Sumador:
    def __init__(self, numeros):
        self.numeros = numeros

    def total_dobles(self):
        return sum(n * 2 for n in self.numeros)

print(Sumador([3, 4, 5]).total_dobles())

Salida al ejecutarlo: 24

03Actividades de práctica

Cada actividad indica cuándo terminaste. No pases a la siguiente hasta cumplirlo.

Actividad 1 · Línea de tiempo con fuentes

Individual · 40 min
  1. Elige 6 lenguajes de la tabla y agrega 2 que no estén en ella.
  2. Para cada uno anota: año, propósito, paradigma principal y forma de traducción.
  3. Cada dato debe tener una fuente de acceso abierto. Puedes partir de la bibliografía de esta unidad.
  4. Ordénalos en una línea de tiempo.
  5. Escribe 3 oraciones sobre la relación que ves entre la época y el propósito de cada lenguaje.

Terminaste cuando tu línea tiene 8 lenguajes, cada dato tiene su fuente y tus 3 oraciones usan ejemplos de tu propia línea.

Actividad 2 · ¿Qué paradigma elegirías?

En equipo de trabajo · 30 min

Casos: (a) una aplicación de turnos para un consultorio, con cambios de horario y cancelaciones; (b) el procesamiento de lecturas de pluviómetros de todo un país; (c) un sistema que recomienda cultivos a partir de reglas sobre el tipo de suelo; (d) la pantalla táctil de un kiosco de autoservicio.

  1. Lean los cuatro casos.
  2. Elijan un paradigma principal para cada caso.
  3. Justifiquen cada elección con una característica del paradigma (no con un lenguaje) y citen la fuente de esa característica.
  4. Indiquen qué parte del caso sería más difícil con otro paradigma.

Terminaste cuando los 4 casos tienen paradigma, una justificación con cita y una comparación con otro paradigma.

Actividad 3 · Error de sintaxis o excepción

Individual · 20 min
  1. En Colab escribe un programa Python de 5 líneas: un print en la línea 1 y un error de sintaxis en la línea 5 (por ejemplo, un if sin dos puntos).
  2. Ejecuta y guarda una captura del resultado.
  3. Reemplaza el error de sintaxis por un error de ejecución, como print(1 / 0), y vuelve a ejecutar.
  4. Compara las dos capturas con lo que dice el tutorial de Python sobre errores de sintaxis y excepciones.

Terminaste cuando puedes explicar, con tus dos capturas y la fuente, por qué en un caso se imprimió la línea 1 y en el otro no.
