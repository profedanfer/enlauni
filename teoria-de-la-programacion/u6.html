01Repaso

Procedimiento y función

Un procedimiento es un bloque con nombre que se invoca para ejecutar acciones; una función además devuelve un valor. En Python, incluso una función sin return devuelve un valor: None (Python Software Foundation, s.f.-b).

Parámetro y argumento

El parámetro formal aparece en la definición: def sumar(a, b). El argumento o parámetro real es lo que se pasa en la llamada: sumar(3, x). Al llamar a la función, los argumentos se introducen en su tabla de símbolos local (Python Software Foundation, s.f.-b).

Activación

Cada llamada, también las recursivas, crea una nueva tabla de símbolos local (Python Software Foundation, s.f.-b). En una máquina virtual, cada llamada tiene un marco (call frame): una ventana dentro de la pila donde la función guarda sus variables locales. Su posición se determina en tiempo de ejecución (Nystrom, 2021).

La lista ordenada de métodos llamados hasta llegar al actual se llama pila de llamadas (Oracle, s.f.-c).

Recursión y desborde

En una recursión, cada llamada deja una operación en espera; esas llamadas en espera, con sus argumentos, se guardan en la pila. Si la recursión nunca termina, se produce un desborde de pila (stack overflow) (Gallardo et al., 2025a, §1.1).

En Python, sys.getrecursionlimit() devuelve la profundidad máxima de la pila del intérprete (Python Software Foundation, s.f.-d); al superarla se lanza RecursionError (Python Software Foundation, s.f.-a).

Paso por valor

Se copia el valor del argumento en el parámetro. En Java, los argumentos primitivos se pasan por valor: los cambios existen solo dentro del método (Oracle, s.f.-a). C siempre usa paso por valor (Question 4.11, s.f.).

Paso por referencia

El parámetro es otro nombre de la misma variable del llamador. C no tiene nada equivalente al paso por referencia formal ni a los parámetros referencia de C++; se imita pasando punteros con el operador & (Question 4.11, s.f.).

Referencias a objetos

Java también pasa por valor las referencias a objetos: al volver del método, la referencia sigue apuntando al mismo objeto, aunque los campos del objeto sí pueden haber cambiado (Oracle, s.f.-a).

Python pasa los argumentos por valor, donde el valor es siempre una referencia al objeto; el tutorial aclara que «llamada por referencia de objeto» sería una mejor descripción (Python Software Foundation, s.f.-b). Como la asignación solo crea referencias, no hay alias entre el nombre del argumento en quien llama y en la función (Python Software Foundation, s.f.-c).

Ambiente

Conjunto de variables disponibles en una parte del programa o de su ejecución (Gallardo et al., 2025b, §4). En Python se busca primero en la tabla local, luego en la de las funciones envolventes, después en la global y al final en la de nombres predefinidos (Python Software Foundation, s.f.-b).

Asignación de memoria

En C, las variables locales tienen duración automática (de la entrada a la salida del bloque) y la memoria pedida con funciones de asignación dinámica dura hasta que se libera (cppreference.com, s.f.). En Java, los objetos se crean con new y el recolector de basura libera los que ya no tienen referencias (Oracle, s.f.-b).

Lenguaje¿Qué se pasa?¿Los cambios se ven afuera?
C, valor comúnUna copia del valor (Question 4.11, s.f.)No
C, punteroUna copia de la dirección (Question 4.11, s.f.)Sí, si se modifica *p
Java, primitivosUna copia del valor (Oracle, s.f.-a)No (Oracle, s.f.-a)

No confundas

Que una lista cambie dentro de una función no prueba que Python pase por referencia. El parámetro y el argumento apuntan al mismo objeto, pero no son alias (Python Software Foundation, s.f.-c; Python Software Foundation, s.f.-b). Si dentro de la función haces lista = [], la de afuera no cambia.

02Código comparado

¿Qué cambia afuera después de la llamada?

Cada función recibe un número y algo que apunta a datos del llamador. Solo cambia afuera lo que se modifica a través de esa referencia.

def cambiar(n, lista):
    n = 99              # reasigna el parámetro local
    lista.append(99)    # modifica el objeto compartido

x = 1
datos = [1]
cambiar(x, datos)
print(x, datos)

Salida al ejecutarlo: 1 [1, 99]

import java.util.ArrayList;
import java.util.List;

public class Paso {
    static void cambiar(int n, List<Integer> lista) {
        n = 99;           // copia local
        lista.add(99);    // el objeto es el mismo
    }

    public static void main(String[] args) {
        int x = 1;
        List<Integer> datos = new ArrayList<>(List.of(1));
        cambiar(x, datos);
        System.out.println(x + " " + datos);
    }
}

Salida al ejecutarlo: 1 [1, 99]

#include <stdio.h>

void cambiar(int n, int *p) {
    n = 99;      /* copia local */
    *p = 99;     /* modifica la variable original */
}

int main(void) {
    int x = 1, y = 1;
    cambiar(x, &y);
    printf("%d %d\n", x, y);
    return 0;
}

Salida al ejecutarlo: 1 99

Actividad 1 · La pila en Python Tutor

Individual · 30 min

Usa este código:

def cuadrado(n):
    return n * n

def suma_cuadrados(a, b):
    return cuadrado(a) + cuadrado(b)

print(suma_cuadrados(3, 4))
  1. Ejecútalo paso a paso en pythontutor.com.
  2. Dibuja la pila en el momento de mayor profundidad.
  3. Anota qué contiene cada marco: parámetros, locales y valor de retorno.
  4. Cuenta cuántos marcos de función se crean en total durante la ejecución.

Terminaste cuando tu dibujo coincide con lo que muestra la herramienta y el conteo de marcos está justificado paso a paso.

Actividad 2 · Predice antes de ejecutar

En equipo de trabajo · 40 min
  1. Copien los tres programas de «Código comparado».
  2. Antes de ejecutar, cambien los valores iniciales y escriban qué creen que se imprimirá.
  3. Agreguen dentro de cambiar una línea que reasigne la lista (Python: lista = [0]; Java: lista = new ArrayList<>();) antes de agregar el 99.
  4. Ejecuten y comparen con su predicción.

Terminaste cuando tienen predicción y resultado para cada versión, y explican con las palabras «copia» y «referencia» por qué la reasignación no se ve afuera.

Actividad 3 · Recursión y desborde

Individual · 25 min
  1. Escribe en Python una función factorial recursiva.
  2. Calcula factorial(5) y dibuja la pila de llamadas.
  3. Llama a factorial(5000) y anota el error exacto.
  4. Consulta sys.getrecursionlimit() y explica la relación entre ese límite y los marcos de la pila.

Terminaste cuando tienes el dibujo de la pila, el nombre exacto del error y una explicación de 3 oraciones.
