01Repaso

Programa funcional

En programación funcional, un programa es un conjunto de funciones matemáticas que convierten entradas en salidas, sin estado interno ni efectos laterales (Gallardo et al., 2025, §1.1.1). Es un tipo de programación declarativa: se declaran valores y relaciones, sin mutación ni secuencias de pasos (Gallardo et al., 2025, §1.3.1).

El artículo original de Lisp, de John McCarthy, se publicó en Communications of the ACM en abril de 1960 (McCarthy, 1960).

Función pura

No modifica sus parámetros, devuelve un único resultado y no tiene estado local ni depende de un estado exterior mutable; por eso siempre devuelve lo mismo con los mismos argumentos (Gallardo et al., 2025, §1.2.4). La documentación de Python llama puramente funcionales a las funciones sin efectos secundarios, cuya salida depende solo de su entrada (Kuchling, s.f.).

Efecto secundario

Cambio que modifica el estado interno o que no se refleja en el valor de retorno de la función (Kuchling, s.f.). Hughes señala que los programas funcionales no tienen sentencias de asignación ni efectos secundarios (Hughes, 1989).

Inmutabilidad

Un objeto inmutable tiene un valor fijo; para guardar un valor distinto hay que crear un objeto nuevo. En Python son inmutables los números, las cadenas y las tuplas (Python Software Foundation, s.f.-c).

Funciones como datos

En el paradigma funcional las funciones son tipos de datos primitivos: hay expresiones lambda y funciones de orden superior (Gallardo et al., 2025, §1.1.1). En Python, lambda crea una función anónima que devuelve el valor de una sola expresión (Kuchling, s.f.). En Java, las expresiones lambda permiten tratar la funcionalidad como argumento de un método, es decir, el código como dato (Oracle, s.f.-b).

map, filter y reduce
  • map devuelve un iterador que aplica una función a cada elemento (Python Software Foundation, s.f.-a).
  • filter devuelve un iterador sobre los elementos que cumplen una condición (Kuchling, s.f.).
  • functools.reduce aplica una función de dos argumentos de forma acumulativa, de izquierda a derecha, hasta obtener un solo valor (Python Software Foundation, s.f.-b).
  • En Java, reduce recibe un elemento identidad (valor inicial) y una función acumuladora (Oracle, s.f.-d).
Composición y pipelines

La salida de una función es la entrada de la siguiente (Gallardo et al., 2025, §1.2.5). En Java, un pipeline tiene una fuente, cero o más operaciones intermedias, como filter, y una operación terminal (Oracle, s.f.-a). Hughes sostiene que las funciones de orden superior y la evaluación perezosa son el «pegamento» que mejora la modularidad (Hughes, 1989).

Evaluación diferida

Una expresión es perezosa si su valor se calcula solo cuando se necesita. En Java, todas las operaciones intermedias de un stream son perezosas: no procesan nada hasta que empieza la operación terminal (Oracle, s.f.-c). En Python, map y filter devuelven iteradores (Kuchling, s.f.).

Funcional con tipado estático

Java combina lambdas y streams con su tipado estático (Oracle, s.f.-e), así que muchos errores de tipo en un pipeline aparecen al compilar. Haskell es un lenguaje puramente funcional cuyo sistema de tipos infiere los tipos correctos aunque no se escriban (Hudak et al., 1999).

No confundas

Usar lambda no vuelve funcional a un programa. Si la lambda modifica una lista de afuera, tiene un efecto secundario. El tutorial de Java recomienda no pasar nunca lambdas con efectos secundarios a operaciones como filter y map (Oracle, s.f.-c).

02Código comparado

Del bucle al pipeline

Total de los productos de más de 10 000 guaraníes, con 10 % de descuento. Python y Java lo declaran como una cadena de transformaciones; C lo resuelve con un bucle y un acumulador.

from functools import reduce

precios = [12000, 8000, 25000, 5000]    # en guaraníes

caros    = list(filter(lambda p: p > 10000, precios))
con_desc = list(map(lambda p: p * 9 // 10, caros))
total    = reduce(lambda a, b: a + b, con_desc, 0)

print(caros)       # [12000, 25000]
print(con_desc)    # [10800, 22500]
print(total)       # 33300
print(precios)     # la lista original no cambió

Salida al ejecutarlo: [12000, 25000] / [10800, 22500] / 33300 / [12000, 8000, 25000, 5000]

import java.util.List;

public class Precios {
    public static void main(String[] args) {
        List<Integer> precios = List.of(12000, 8000, 25000, 5000);
        int total = precios.stream()
                .filter(p -> p > 10000)
                .map(p -> p * 9 / 10)
                .reduce(0, Integer::sum);
        System.out.println(total);
    }
}

Salida al ejecutarlo: 33300

#include <stdio.h>

int main(void) {
    int precios[] = {12000, 8000, 25000, 5000};
    int total = 0;                       /* estado que cambia */
    for (int i = 0; i < 4; i++) {
        if (precios[i] > 10000)
            total += precios[i] * 9 / 10;
    }
    printf("%d\n", total);
    return 0;
}

Salida al ejecutarlo: 33300

Actividad 1 · Del bucle al pipeline

Individual · 35 min

Parte de este código imperativo:

ventas = [("Luque", 550000), ("San Lorenzo", 400000),
          ("Luque", 400000), ("Limpio", 720000)]

total_luque = 0
for ciudad, monto in ventas:
    if ciudad == "Luque":
        total_luque = total_luque + monto
print(total_luque)
  1. Identifica qué variable cambia de estado en cada vuelta.
  2. Reescríbelo con filter y map (o comprensiones) y sum.
  3. Reescríbelo otra vez con reduce.
  4. Verifica que las tres versiones impriman el mismo resultado.

Terminaste cuando tienes tres versiones que imprimen lo mismo y ninguna de las funcionales modifica variables fuera de su expresión.

Actividad 2 · ¿Pura o impura?

En equipo de trabajo · 30 min

Funciones para analizar:

import random

def a(x):
    return x * 2

contador = 0
def b(x):
    global contador
    contador += 1
    return x + contador

def c(lista):
    lista.append(0)
    return lista

def d(lista):
    return lista + [0]

def e(nombre):
    print("Hola", nombre)

def f(n):
    return n + random.randint(1, 6)
  1. Clasifiquen cada función como pura o impura, usando las condiciones de una función pura citadas en esta unidad.
  2. Para cada impura, nombren el efecto secundario o la dependencia externa.
  3. Reescriban dos funciones impuras como puras.
  4. Demuestren con dos llamadas iguales que sus versiones puras devuelven lo mismo.

Terminaste cuando las 6 funciones están clasificadas con justificación y las 2 reescrituras pasan la prueba de las dos llamadas.
